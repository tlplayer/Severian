## Source block → MIR → checks

`sev` blocks are source/test examples. `text` blocks specify expected IR and assertions; their notation is not an implemented inspection API. All scenarios are requirements, not reported test results. Humans run tests.

### Addition and assignment

```sev
def add(x: int, y: int) -> int:
    z = x + y
    return z

test "addition returns the assigned value":
    assert(add(2, 3) == 5)
```

```text
HIR source block: add
  parameters: x: int, y: int
  contents: [bind z = selected_add(x, y), return z]

MIR realization: add[int, int]
  B0(x: int, y: int):
    V0: int = selected_add(x, y)
    bind z = V0
    Finish(V0)

Ownership facts at Finish:
  x: {initialized: true, moved: false, loans: [], cleanup: none}
  y: {initialized: true, moved: false, loans: [], cleanup: none}
  z: {initialized: true, moved: false, loans: [], cleanup: none}

assert body.entry == B0
assert B0.terminator.result.type == int
assert addition.provider == HIR.selected_add.provider
assert addition.origin == source span of "x + y"
assert assignment.effect == resolved binding contract
assert cfg.valid and ownership.valid
assert verify(state) produces ReadyMir

MIR pipeline on one shared execution graph:
  build CFG → check CFG → analyze ownership → insert required cleanup
  → recheck CFG and ownership → ReadyMir → LIR
assert CFG edges and ownership facts refer to the same realization/body
```

### Program → package → module → submodule → block → operations

```text
Source request:
  program: demo
  package: calculator
  module: arithmetic
  file: add.sev
  source: add and its test above

Required membership:
  Program(demo)
    Package(calculator)
      Module(arithmetic)
        Submodule(add's dependency component)
          source Block(add)
            realization add[int, int]
              execution Block(B0)
                [selected_add, bind, Finish]

Current HIR fields:
  Program.graph, Program.modules, Program.submodules
  Module.package: string

Missing implementation:
  Program.packages and explicit package → module membership

assert HIR and MIR refer to the same source BlockAddress
assert each module belongs to its requested package
assert each submodule retains its HIR members
assert nested execution regions retain their partition_owner membership
assert MIR operations retain source origins through LIR
assert build roots exclude the test unless a test request selects it
```

### Two specializations of one callable

```text
Fixture: resolved identity[T](value: T) -> T
Calls: identity[int](7), identity[bool](true)

realizations:
  (identity.definition, T=int):
    B0(V0: int): Finish(V0)
  (identity.definition, T=bool):
    B0(V0: bool): Finish(V0)

assert realization keys differ
assert each V0 and B0 is qualified by its realization
assert source definition is shared and unchanged
assert each realization has its own CFG and ownership result
assert persistent keys use semantic identities, not type-table positions
```

### Recursion, provider failure, and stale analysis

```text
test "recursive roots":
  input dependencies: first → second, second → first; unused is independent
  roots: [first]
  assert register(first.signature, second.signature) precedes body expansion
  assert realizations == {first, second}
  assert unused has no emitted realization
  assert initializers preserve declared order

test "provider selection":
  zero matching providers → source diagnostic; no ReadyMir
  two matching providers → ambiguity diagnostic; no ReadyMir
  selected provider fails → its diagnostic; no fallback provider
  unknown operation effects → diagnostic; never assume pure
  external callable → require complete ABI/effect contract
  intrinsic callable → require explicit provider contract
  defined callable without body → diagnostic

test "readiness follows all inputs":
  ready = verify(state)
  for changed input in [body, substitution, callee, type, provider, program]:
    invalidate(state, changed input)
    assert old ready cannot authorize lowering
  insert cleanup or coverage operations
  assert CFG and ownership are reverified before new readiness
  render report twice
  assert no additional cleanup or coverage operations
```

## Responsibilities

| Owner | Responsibility |
|---|---|
| Frontend / HIR | Select grammar, retain concrete semantic results, resolve required declarations and record dependency partitions. |
| Semantic provider | Specify operand/result types, evaluation order, effects and executable expansion; report unsupported contracts. |
| MIR coordinator | Select roots, discover realization dependencies, apply substitutions and coordinate analysis. |
| CFG | Build and verify execution paths as specified in [SIP-0028](0028-CFG.md). |
| Ownership | Analyze storage, moves, loans and cleanup as specified in [SIP-0027](0027-Ownership.md). |
| LIR | Choose target representations and conversions after MIR readiness, per [SIP-0029](0029-LIR.md). |

## Data Models

```text
MirState
  program: reference to Program
  roots: ExecutionRoots
  realizations: RealizationKey -> Realization
  analyses: results tied to their input revisions

Realization
  key: resolved definition + canonical generic substitution
  declaration: reference to resolved callable contract
  source: BlockAddress or explicit generated/external provenance
  parameters, values: realization-local identities and types
  body: CfgBody when defined
  effects, ownership: checked contracts/results
  revision: execution revision
```

## API

```text
prepare(program: Program, roots: ExecutionRoots) -> MirState | diagnostics
verify(state: MirState) -> ReadyMir | diagnostics
invalidate(state: MirState, change: declared mutation) -> unit
```

| Location | Responsibility |
