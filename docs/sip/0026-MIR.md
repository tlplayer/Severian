# SIP-0026: MIR on the Shared Block Graph

Status: Draft — WIP skeleton
Type: Compiler
Created: 2026-10-03
Target: `sev_compiler/mir`

## Context

Source and syntax → lexer → parser block graph → HIR submodules and logical modules → MIR executable modules → LIR. MIR enriches the components HIR hands it; it does not reconstruct an AST or maintain another copy of the semantic hierarchy.

The starting contracts are [Program, Submodule, Module](../../sev_compiler/hir/hir/src/program.sev), [BlockGraph and BlockAddress](../../sev_compiler/hir/hir/src/dependencies.sev), and [Block](../../sev_compiler/syntax/block/block.sev). [MIR's model](../../sev_compiler/mir/mir/src/model.sev) already reexports these. The interfaces below are proposals, not implemented APIs.

## Data model

| Component | Contract |
| --- | --- |
| `Program.graph` | Canonical source blocks, resolved nodes, bindings, types, expressions and dependency edges. |
| `Program.submodules` | HIR's dependency partitions; MIR retains membership and dependencies. |
| `Program.modules` | Logical module membership supplied by HIR; MIR attaches executable bodies and resolved callable interfaces. |
| `BlockAddress(unit, block)` | `unit` indexes `graph.units`, a table of source files and package/module metadata. `block` is file-local. Neither index is a persistent symbol identity. |
| `Block` | Shared contract for source and execution blocks, including operations, parameters, terminators and provenance. |
| Proposed `MirAnalysis` | References the same `Program`; indexes callable realizations, CFG bodies and ownership results. Contains analysis state, not copied modules or blocks. |

Each callable realization needs its resolved definition identity and generic substitution. Local/value/CFG indices are qualified by that realization. Serialized interfaces use semantic identities, never temporary table positions.

## Interfaces and flow

Proposed contracts, in pseudocode:

```text
prepare_mir(program: Program) -> MirAnalysis | diagnostics
verify_mir(analysis: MirAnalysis) -> success | diagnostics
lower(analysis: MirAnalysis, request: LoweringRequest) -> LoweringResult | diagnostics
```

`prepare_mir` requires resolved names, types, operations and HIR partitions. It builds callable CFGs through [SIP-0028](0028-CFG.md), then checks ownership through [SIP-0027](0027-Ownership.md). Modules become executable views of their existing submodules; file boundaries do not determine compilation boundaries.

Each pass declares the fields it reads/writes and the analyses it invalidates. Verification results refer to a specific graph/body revision. Changed operations or edges require fresh CFG and ownership verification before LIR can consume them. Failure yields diagnostics with source provenance, never a partially ready module.

## Problems to avoid

- Keep containment, compilation dependencies and control-flow edges distinct. A nested block does not automatically create a dependency or a runtime edge.
- Grammar/type providers supply semantics. MIR must not rediscover meaning from token spelling or add a central case for every source block kind.
- Import contracts from their defining packages. Retire the old `hir/modules/module.sev` dependencies as consumers migrate; do not recreate the old hierarchy as a compatibility model.
- Preserve source ownership, ordering and spans while adding execution information. `partition_owner` controls compilation grouping, not value ownership.

## Testing

Extend the [HIR pipeline tests](0021-Semantic.md): nested execution retains source identities; recursive functions retain their submodule and resolved calls; ambiguity stops before MIR. Assert that a changed CFG invalidates ownership results and that diagnostics prevent LIR entry.

## Open work

Specify callable realization keys, analysis storage/revisions and the readiness verifier. Port consumers incrementally against these interfaces; the current frontend dependency-resolution gaps remain prerequisites.
