# SIP-0029: LIR Lowering and MLIR Emission

Status: Draft — WIP skeleton
Type: Compiler
Created: 2026-10-03
Target: `sev_compiler/lir/lowering`, `sev_compiler/lir/mlir`

## Context

LIR consumes verified [MIR](0026-MIR.md) modules over the shared HIR program, lowers their executable operations into typed MLIR, then coordinates compilation and linking through the backend/package interfaces. It retains source and semantic identities through target realization.

Lowering maps semantic operations/types to target operations/types. The MLIR component owns target IR construction, verification and serialization. It must not repeat name resolution, grammar selection, HIR partitioning or ownership inference.

## Data model

| Component | Contract |
| --- | --- |
| Input `MirAnalysis` | Same `Program`, modules, submodules and shared blocks, with verified CFG/ownership for the current revision. |
| Proposed `LoweringRequest` | Selected module/submodule indices in that program, target/ABI settings, exports and requested artifact kind. |
| Existing `LoweredOperation`, `LoweredType`, MLIR bindings | Target realizations supplied through operation/type providers; retain the originating semantic identity and source provenance. |
| Existing `MlirProgram`, `MlirRegion`, `MlirBlock`, `MlirValue` | Typed backend representation. Explicit maps connect semantic definitions/values and qualified CFG positions to backend identities. |
| Proposed `LoweringResult` | Verified MLIR plus origin/identity maps and emission plan. References the input program; does not duplicate its hierarchy. |
| Proposed emission group | Selected callable realizations, target, exports/imports and artifact destination. Records contributing HIR submodules. |

HIR submodule membership stays fixed during emission. An emission group may split one submodule or combine several; that is artifact planning, not a semantic repartition. Files, modules, submodules and object files need not correspond one-to-one.

## Interfaces and flow

Proposed contracts, in pseudocode:

```text
lower(analysis: MirAnalysis, request: LoweringRequest)
    -> LoweringResult | diagnostics
verify_mlir(result: LoweringResult) -> success | diagnostics
emit(result: LoweringResult, backend_request) -> artifacts | diagnostics
link(artifacts, package_link_request) -> artifact | diagnostics
```

Lowering resolves declared target capabilities and type layouts, maps CFG parameters/edges and operations, and retains cleanup/effect ordering. Literal payloads come from the type-owned `LiteralValue` contract; a missing or ambiguous lowering provider is diagnosed rather than replaced with a default representation.

The MLIR layer builds structured IR before printing text. Backend verification precedes artifact emission. Exported definitions, ABI/layout decisions and external references must agree between emitted objects and package interface metadata. Linking follows the resolved artifact dependency plan.

## Problems to avoid

- Use the shared `Program` and resolved identities instead of restoring the deleted HIR module model expected by current lowering imports.
- Do not introduce another source-language block/type enum in the emitter. New syntax lowers through resolved operations and declared providers.
- Keep one authoritative lowering result per target/configuration/revision; define whether `Block.lowered_operations` stores it or references it before adding caches.
- Reject incomplete MIR and unsupported targets with source diagnostics. Do not silently omit operations or fall back to string-based inference.

## Testing

Extend the source → HIR tests through real MIR and typed MLIR: preserve nested control flow and source locations; emit the recursive pair and independent function with correct symbol references; stop ambiguous or ownership-invalid input before emission. Add an object/interface/link round trip and a missing-provider diagnostic case.

## Open work

Specify provider dispatch, ABI/layout authority, emission-group identities and package metadata mapping. Port lowering and MLIR consumers to the shared contracts; exact pass pipelines and backend options remain WIP.
