## MIR → target representation → checks

`atom` blocks specify proposed lowering records and assertions. Target choices are explicit fixture inputs. These are test requirements, not implemented inspection APIs or executed results. Humans run tests.

| Example | MIR input | LIR decision |
|---|---|---|
| `x + y` | Selected typed addition and overflow contract | Target type and addition implementation |
| Record argument | One semantic record value | Aggregate, field values, or address per ABI |
| `items[index]` | Selected indexing and failure contract | Bounds check, address computation, load |
| Memory atomic | Storage, ordering, scope and lifetime | Supported synchronized target operation |

### Scalar addition

```sev
def add(x: i32, y: i32) -> i32:
    return x + y

test "typed addition":
    assert(add(2, 3) == 5)
```

```text
MIR:
  B0(x: i32, y: i32):
    V0: i32 = selected_add(x, y)
    Finish(V0)

Lowering inputs:
  input: ReadyMir for this realization and its dependencies
  type provider: i32 → target integer(bits=32)
  operation provider: selected_add → implementation preserving overflow contract
  ABI: two scalar arguments, one scalar result

Lowering maps:
  (add, x) → [%x: target.i32]
  (add, y) → [%y: target.i32]
  (add, V0) → [%sum: target.i32]
  (add, B0) → target.entry

assert target addition has two i32 operands and one i32 result
assert overflow/failure behavior matches selected_add's contract
assert origin(%sum producer) == source span of "x + y"
assert source conversions were already resolved before lowering
assert no runtime requirement is inferred from a function's spelling
```

### One record becomes two ABI arguments

```sev
class Pair:
    x: i32
    y: i32

def sum_pair(pair: Pair) -> i32:
    return pair.x + pair.y

test "record call preserves fields":
    assert(sum_pair(Pair(2, 3)) == 5)
```

```text
Fixture ABI: Pair uses two scalar i32 arguments.

MIR signature: sum_pair(pair: Pair) -> i32
MIR call: V0 = call sum_pair(Pair(2, 3))

Target signature: sum_pair(%x: i32, %y: i32) -> i32
Target call: %result = call sum_pair(%two, %three)
ValueMap[(caller, pair)] = [%two, %three]

assert caller and callee have identical expanded argument contracts
assert fields retain order x, y
assert record returns and CFG edge arguments use the same conversion
assert unit result maps to zero target values where ABI specifies that
assert required adapters retain source and callable origins

second target ABI: Pair passed by address
assert second lowering has separate values, blocks and symbols
assert first target result and shared HIR source are unchanged
```

### Indexing expands one semantic operation

```sev
def first(items: list[int]) -> int:
    return items[0]

test "indexing returns the selected element":
    assert(first([7, 8]) == 7)
```

```text
MIR:
  V0 = selected_index(view items, 0)
  Finish(V0)

Fixture target implementation:
  %length = collection_length(%items)
  %valid = in_bounds(0, %length)
  branch %valid → read, failure
  read: %address = element_address(%items, 0)
        %value = load(%address)
        return %value
  failure: preserve selected_index's declared failure behavior

assert bounds check precedes load on every read path
assert items is evaluated once
assert ownership/lifetime contract remains satisfied
assert an unsupported failure path prevents artifact emission
```

### Provider selection, synchronization, and readiness

```text
test "provider selection":
  missing provider → source diagnostic, no result
  ambiguous providers → source diagnostic, no construction
  selected provider fails → no fallback to a different provider
  register a valid custom operation provider → no parser/keyword changes

test "memory atomic":
  input operation: atomic load(place, ordering=acquire, scope=system)
  target supports contract → preserve ordering, scope and storage lifetime
  target lacks contract → reject
  assert ordinary load is never substituted
  assert semantic add being an atomic step does not imply synchronization

test "lowering inputs and outputs":
  change MIR or provider revision → reject stale ReadyMir/result
  rewrite changes storage lifetime → require checked preservation or reanalysis
  assert every reachable operation is converted or legal in destination
  assert runtime/import requirements come from selected reachable providers
  assert recursive/external calls use stable semantic symbol identities
  assert emission groups reference contributing HIR submodules
  assert splitting/combining emission groups preserves HIR membership
  assert package flow owns target requests, output paths, cache and linking
```

## Responsibilities

| Owner | Responsibility |
|---|---|
| MIR | Provide resolved executable operations, callable contracts and current ownership/CFG verification. |
| Type provider | Declare valid representations, layouts and conversion rules for supported targets. |
| Operation provider | Declare legal target implementations, prerequisites and preserved effects. |
| LIR | Select implementations, map values/calls/edges, assemble emission groups and validate conversion coverage. |
| MLIR | Construct and verify typed IR, execute the declared dialect conversion plan and emit backend artifacts. |
| Package flow | Select build targets, coordinate artifact dependencies, cache outputs and link them. |

## Data Models

```text
LoweringRequest
  target and ABI contract
  selected realization identities
  exports: resolved definition -> requested external symbol
  artifact kind and declared target options

LoweringContext
  input: ReadyMir reference
  request: LoweringRequest
  value map: (realization, ValueId) -> ordered target values
  block map: (realization, CFG position) -> target control destination
  symbol map: realization identity -> target symbol
  origin map: generated operation -> semantic/source provenance

LoweringResult
  typed target program
  identity/origin maps
  requirements and emission groups
  input and provider revision identities
```

## API

```text
select(operation, request: LoweringRequest) -> LoweringProvider | diagnostics
lower(input: ReadyMir, request: LoweringRequest) -> LoweringResult | diagnostics
verify(result: LoweringResult) -> checked result | diagnostics
```
