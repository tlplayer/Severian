# Severian laboratories

Laboratories are proving grounds for substantial systems work. They may use
hosted models and narrow native boundaries while their behavior, tests,
coverage, mutation score, and memory safety are established. Components move
into production packages only after those gates pass.

| Laboratory | Purpose |
| --- | --- |
| [`01-container-database`](01-container-database/) | OCI runtime bundles, source-defined file-format dispatch, TCP service boundaries, and local package publication. |
| [`02-orchestrator-llm`](02-orchestrator-llm/) | Three OCI/CDI model replicas, tensor-backed generation, health monitoring, readiness-gated routing, metrics, and recovery policy. |
| [`distributed_systems`](distributed_systems/) | Serialization, RPC, consensus, replication, sharding, and deterministic fault testing. |
| [`operating_system`](operating_system/) | Clean-room Unix-like kernel work following university-lab milestones from hosted invariants toward a freestanding RISC-V target. |
| [`space_station`](space_station/) | Tile-based orbital-station simulation stressing graphics, typed channel workers, deterministic replay, and native TCP observers. |
